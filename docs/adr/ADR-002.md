# ADR-002: Camadas Unidirecionais (`ui → services → core`)

- **Status:** Aceito
- **Data:** 2026-08-01
- **Decisores:** jr (Tech Lead), ATLAS (Arquiteto)
- **Referenciado em:** `ARCHITECTURE.md` §2, vários `__init__.py`

## Contexto

O projeto cresceu de um único módulo (`hash_checker.py`) para uma plataforma com 5 camadas: UI (CLI + servidor HTTP), Services (report, history), Plugins (LogAnalyzer, HashCheckerPlugin) e Core (crypto, filesystem, validators, exceptions, config).

Com mais módulos, surgem riscos de acoplamento indevido. `ui` que depende de `core.exceptions` é aceitável; `core` dependendo de `ui` seria um erro. Sem uma regra explícita, novos desenvolvedores podem fazer imports reversos quebrando testabilidade.

## Decisão

**A direção de dependências é estritamente unidirecional:**
```
ui (CLI/HTTP) → services (report/history) → plugins → core (algorithms/models)
```

Regras:
1. **Nada no Core importa de `services`, `plugins`, `cli`, `ui`** (desde a Sprint 2)
2. **Nada nos plugins importa de `services`, `cli`, `ui`** (exceção: plugins podem importar core)
3. **Services podem importar de core e plugins**
4. **CLI e UI podem importar de tudo abaixo**

Isso mantém o core 100% independente e testável sem qualquer infrastructure — perfaz princípio Clean Architecture.

## Consequências

### Positivas
- ✅ **Testabilidade** — core testado em uma unidade pura, sem mockar interfaces
- ✅ **Clareza** — novas pessoas entendem imediatamente o fluxo de dependência
- ✅ **Segurança** — evita vazamento de dependências indevidas

### Negativas
- ⚠️ **Necessidade de shims** — quando o core contém funcionalidade que services usavam originalmente (ex.: `file_utils` → `core/filesystem`), services se tornam shims de re-export
- ⚠️ **Indireção** — chamadores agora precisam importar de `core/exceptions/domain` (deep), mas shims mitigam

## Pendências

- Verificação automática via CI: checar que nenhum import do core inclui `app.services`, `app.plugins`, `app.cli` ou `app.ui` (sugestão: script de auditoria como pre-commit hook)
