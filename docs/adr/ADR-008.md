# ADR-008: Configuração via dataclass Settings + variáveis de ambiente EDY_*

- **Status:** Aceito
- **Data:** 2026-08-01
- **Decisores:** jr (Tech Lead), ATLAS (Arquiteto)
- **Implementação:** VULCAN (Missão 3 da Sprint 2)
- **Documentação:** NOVA (Missão 4)

## Contexto

A aplicação precisava de uma forma central e segura de configuração para o Hash Checker: o
usuário deve poder ajustar o algoritmo padrão, o nível de log, a raiz permitida, o tamanho de
chunk e o encoding — sem depender de um arquivo de configuração em disco, que adicionaria
complexidade (parse, validação, caminho do arquivo, segurança) a uma CLI local.

Requisitos:

- **Zero dependências** (ADR-001 — core 100% stdlib);
- **Fonte única de configuração** — nenhum módulo lê `os.environ` espalhado;
- **Padrões seguros** por default (SHA-256, INFO, cwd, 64 KB, utf-8);
- **Validação de tipos** com mensagens claras (nunca `TypeError` obscuro de conversão);
- **Imutabilidade** — a configuração não muda em runtime;
- **Testável** — fácil mockar via ambiente.

Alternativas consideradas:

| Opção | Prós | Contras |
|-------|------|---------|
| **`dataclass` frozen + env `EDY_*`** | Zero deps; imutável; tipado; simples; adequado a CLI local | Sem arquivo de config; menos flexível para deployments complexos |
| **Arquivo `.env`/TOML/YAML** | Config persistente | Dependência externa (ou parse manual); mais superfície; desnecessário na v1 |
| **`pydantic-settings`** | Validação rica | **Dependência de terceiros no runtime** (viola ADR-001) |

## Decisão

Adotar uma **`@dataclass(frozen=True, slots=True)` `Settings`** carregada por
**`load_settings()`** a partir de variáveis de ambiente com prefixo **`EDY_`**, sem arquivo de
configuração:

| Variável de ambiente | Campo `Settings` | Default |
|----------------------|------------------|---------|
| `EDY_DEFAULT_HASH_ALGORITHM` | `default_hash_algorithm` | `SHA256` |
| `EDY_LOG_LEVEL` | `log_level` | `INFO` |
| `EDY_ALLOWED_ROOT` | `allowed_root` | `None` (cwd) |
| `EDY_CHUNK_SIZE` | `chunk_size` | `65536` |
| `EDY_TEXT_ENCODING` | `encoding` | `utf-8` |

Regras de contrato:

1. `Settings` é **imutável** (`frozen=True`, `slots=True`).
2. `load_settings()` lê o ambiente **uma única vez** e valida tipos — `EDY_CHUNK_SIZE` inválido
   (não-inteiro ou ≤ 0) levanta `ValueError` com mensagem legível.
3. Nenhum módulo do Core depende de UI/CLI (config é puro stdlib: `os`, `dataclasses`,
   `pathlib`).
4. **Sem arquivo de config na v1** — simplicidade de CLI local; um arquivo pode ser adicionado
   em v2/v3 sem quebrar a API (`load_settings` permanece a fonte única).

## Consequências

### Positivas

- ✅ **Zero deps runtime** (ADR-001) — `dataclasses` + `os` + `pathlib` stdlib.
- ✅ **Padrões seguros** — SHA-256 por padrão; raiz = cwd; encoding utf-8.
- ✅ **Validação clara** — `ValueError` legível em vez de `TypeError` obscuro.
- ✅ **Imutável e tipado** — `mypy strict` passa; sem estado global mutável.
- ✅ **Testável** — `tests/unit/test_config.py` cobre defaults e env (monkeypatch).
- ✅ **Escalável** — adicionar campo = adicionar attr + default; `load_settings` centraliza.

### Negativas / custos

- ⚠️ **Sem configuração persistente** — variáveis de ambiente não sobrevivem a reinícios sem
  setup externo (aceito para CLI local).
- ⚠️ **Sem seção/secrets no arquivo** — adequado para a v1; deployments complexos (v2/v3)
  devem avaliar arquivo de config/secret manager.
- ⚠️ **Prefixo `EDY_` é convenção** — precisa ser documentado (este ADR + README +
  CONTRIBUTING) para novos contribuidores.
