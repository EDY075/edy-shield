# ADR-001: Core 100% stdlib — Zero dependências de terceiros no runtime

- **Status:** Aceito
- **Data:** 2026-08-01
- **Decisores:** jr (Tech Lead), ATLAS (Arquiteto)
- **Referenciado em:** `app/core/algorithms/hash_checker.py`, `pyproject.toml`, `ARCHITECTURE.md` §6

## Contexto

O EDY Shield é uma plataforma de cibersegurança defensiva. No início do projeto, a stack precisava ser definida. Havia tentação de usar bibliotecas como `pydantic`, `click`, `requests` ou até `cryptography` — mas cada dependência externa adiciona:

- **Superfície de ataque** — qualquer transitive dependency pode conter vulnerabilidades (supply chain)
- **Peso de instalação** — o projeto deve ser `pip install edy-shield` e funcionar imediatamente
- **Complexidade de manutenção** — versões conflitantes, breaking changes, segurança de dependências

Python 3.12 inclui `hashlib`, `hmac`, `argparse`, `dataclasses`, `pathlib`, `logging` — suficientes para cobrir 100% das funcionalidades v1 do Hash Checker.

## Decisão

**O Core do EDY Shield (`app/core/`) usa exclusivamente a biblioteca padrão do Python 3.12.** Nenhuma dependência de terceiros no runtime. Isso inclui:

- `hashlib` para hashes criptográficos (SHA-256, SHA-1, MD5)
- `hmac` para comparação em tempo constante (`safe_compare`)
- `pathlib.Path` para validação de paths e segurança de contenção
- `dataclasses` para modelos imutáveis (`HashResult`, `Settings`)
- `argparse` para a CLI (ADR-004/ADR-007)
- `logging` para logging centralizado
- `os` para variáveis de ambiente

**Apenas dependências de desenvolvimento** (`pytest`, `mypy`, `ruff`) são permitidas como dev deps — nunca no runtime.

## Consequências

### Positivas
- ✅ **Segurança máxima** — sem transitive dependencies para auditar ou atualizar
- ✅ **Portabilidade total** — `pip install edy-shield` funciona em qualquer Python 3.12+
- ✅ **Build zero-Docker** necessário
- ✅ **Menor superfície de ataque** no runtime
- ✅ **Adequado para ambientes air-gapped** e compliance rigoroso

### Negativas
- ⚠️ **UX limitada** — não podemos usar `click`/`typer` (CLI), `requests` (API), `bcrypt` (senhas)
- ⚠️ **Mais código manual** — validação de entrada precisa ser escrita, em vez de `pydantic`
- ⚠️ **Crescimento para v2+** pode justificar `streamlit`/`typer` como dependências opcionais

## Pendências

- Se a UI Streamlit (v2) for adotada, `streamlit` seria aceita como dependência opcional, não no Core
- Se API REST exigir autenticação, o Core quebra e `Flask`/`FastAPI` são permitidos como deps opcionais
