Por que um FIM?

Integridade de arquivos é a base da defesa

  • Detectar modificações não autorizadas (malware, tampering)
  • Auditar instalações e atualizações (antes/depois)
  • Detectar arquivos novos (droppers) e removidos (exfiltração)
  • Recomendado por NIST e CIS Controls
EDY Shield · v2.002/2026
Solução

Baseline criptográfica + detecção de mudanças

Baseline

Fotografia do alvo: path relativo, digest SHA-256, tamanho, mtime e permissões — em JSON determinístico.

Scan

Compara o estado atual contra a baseline e classifica: novo · modificado · removido · inalterado.

Digest = fonte de verdadeADR-FIM-002
Arquitetura

Camadas unidirecionais, core puro

ui (CLI + Console SOC) → services (PluginManager · ReportEngine json|txt|html|md) → plugins (file_integrity · hash_checker · log_analyzer) → core/fim (models · scanner · baseline · store) ← NOVO → core (algorithms · filesystem · crypto)
100% stdlib (ADR-001)direção única ui→services→core
Demonstração

Do terminal ao Console

$ edyshield fim baseline criar ./conf Baseline criada: 128 entrada(s) — id fim_sha256_20260802T120000Z $ edyshield fim scan ./conf --baseline baseline.json novo config.tpl modificado app.ini removido old.cert fim: 3 mudança(s) — 1 novo(s), 1 modificado(s), 1 removido(s)
exit 0 = sem mudanças · 1 = mudanças · 2 = erroARES-QA-029
